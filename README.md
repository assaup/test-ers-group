# Справочник сотрудников

Веб-приложение со списком сотрудников компании: регистрация и вход по email, список с поиском по
ФИО и фильтром по отделу, добавление сотрудника.

**Стек:** React 19 + TypeScript + обычный CSS · Node.js + Express 5 + TypeScript · SQLite
(встроенный модуль `node:sqlite`).

## Быстрый старт

Нужен **Node.js 24 или новее** (CI проверяет на 24 и 26).

```bash
git clone https://github.com/assaup/test-ers-group.git
cd test-ers-group
npm install
npm run dev
```

Откройте **http://localhost:5173** и войдите демо-аккаунтом.

### Демо-доступ

| Email              | Пароль      |
| ------------------ | ----------- |
| `demo@example.com` | `demo12345` |

Можно и зарегистрировать свой аккаунт — кнопка «Зарегистрироваться» на странице входа.

При первом запуске сервер сам создаёт базу `server/data/app.db`: таблицы, 5 отделов, 5
демо-сотрудников и демо-аккаунт. Повторные запуски ничего не дублируют, добавленные данные
сохраняются. Чтобы начать с чистой базы, остановите сервер и удалите папку `server/data`.

### Production-режим

Сервер отдаёт и API, и собранный клиент с одного порта:

```bash
npm run build
npm start
```

Откройте **http://localhost:3000** — или `http://<IP-компьютера>:3000` с другого устройства в той
же сети: production-режим работает и по обычному HTTP.

## Что умеет

| Требование задания                          | Как сделано                                                                |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| Регистрация по email и паролю, вход и выход | серверные сессии в SQLite, httpOnly-cookie, выход сразу отзывает сессию    |
| Список доступен только после входа          | гость попадает на `/login`, после входа возвращается туда, куда шёл        |
| API сотрудников требует авторизации         | все `/api/*`, кроме входа, регистрации и `health`, отвечают 401 без сессии |
| Поиск по ФИО                                | без учёта регистра, с кириллицей и «ё» = «е», с задержкой при вводе        |
| Фильтр по отделу                            | вместе с поиском, оба сохраняются в URL                                    |
| Добавление с проверкой обязательных полей   | одни и те же zod-схемы на клиенте и сервере, ошибки под полями             |
| Данные сохраняются после перезапуска        | файл SQLite, покрыто тестом с перезапуском сервера                         |
| Пароли в виде хешей                         | scrypt с солью, токены сессий тоже хранятся только как хеши                |
| 5 демо-сотрудников                          | идемпотентный сид при старте                                               |

Дополнительно: адаптивная вёрстка (таблица превращается в карточки на телефоне), светлая и тёмная
темы, ограничение частоты попыток входа, состояния загрузки, пустого списка и ошибки по
[макету](design/README.md).

## Настройки

Всё работает без настройки. При необходимости можно задать переменные окружения сервера:

| Переменная       | По умолчанию         | Назначение                                                              |
| ---------------- | -------------------- | ----------------------------------------------------------------------- |
| `PORT`           | `3000`               | порт сервера; в `npm run dev` Vite проксирует `/api` на него же         |
| `DB_PATH`        | `server/data/app.db` | путь к файлу базы                                                       |
| `CLIENT_DIR`     | `client/dist`        | папка собранного клиента для production-режима                          |
| `SECURE_COOKIES` | —                    | `true` только за HTTPS: флаг `Secure` у cookie, HSTS и перевод на https |

`npm start` всегда работает в production-режиме (это задаётся при сборке сервера) и отдаёт
собранный клиент. `npm run dev` — режим разработки: клиент отдаёт Vite, а старая сборка из
`client/dist` не используется.

## API

| Метод | Путь                 | Доступ    | Описание                                           |
| ----- | -------------------- | --------- | -------------------------------------------------- |
| POST  | `/api/auth/register` | все       | регистрация, сразу открывает сессию                |
| POST  | `/api/auth/login`    | все       | вход                                               |
| POST  | `/api/auth/logout`   | с сессией | выход                                              |
| GET   | `/api/auth/me`       | с сессией | текущий пользователь                               |
| GET   | `/api/departments`   | с сессией | список отделов                                     |
| GET   | `/api/employees`     | с сессией | список; параметры `search` и `departmentId`        |
| POST  | `/api/employees`     | с сессией | добавление: `{ fullName, position, departmentId }` |

Ошибки приходят в одном формате: `{ "error": { "code", "message", "fields"? } }`. Подробнее — в
[`agents/architecture.md`](agents/architecture.md).

## Структура

```
client/    React-приложение (Vite): страницы, компоненты, хуки, API-клиент
server/    Express API: модули auth / departments / employees, SQLite, миграции, сид
shared/    zod-схемы и типы, общие для клиента и сервера
design/    макет из Claude Design
agents/    архитектура, roadmap, соглашения, дизайн-бриф, ADR
```

Сервер разделён на слои router → service → repository: HTTP отдельно от бизнес-правил, SQL только
в репозиториях.

Ключевые решения с обоснованием и рассмотренными альтернативами:

- [`node:sqlite` и SQL без ORM](agents/decisions/002-node-sqlite.md)
- [Поиск по ФИО с кириллицей и «ё»](agents/decisions/003-cyrillic-search.md)
- [Хеширование паролей через scrypt](agents/decisions/004-password-hashing.md)

## Качество и тесты

- **Тесты (Vitest):**
  - сервер — supertest на настоящем SQLite в памяти, без моков базы: авторизация, доступ,
    поиск, валидация, сценарий пользователя, перезапуск;
  - клиент — Testing Library на всём приложении, подменяется только `fetch`: формы, редиректы,
    поиск и фильтр, гонка запросов, диалог добавления;
  - смоук-тест запускает собранный сервер и проверяет API и клиент.
- **Статические проверки:** TypeScript в strict-режиме, ESLint с правилами `strictTypeChecked`,
  Prettier.
- **Git-хуки:** pre-commit (Husky + lint-staged) проверяет изменённые файлы, commitlint — формат
  [Conventional Commits](https://www.conventionalcommits.org/).
- **CI:** GitHub Actions на каждый push — lint, формат, типы, тесты, сборка, смоук-тест.
