# 004. Хеширование паролей через scrypt из `node:crypto`

**Статус:** принято

## Контекст

Пароли должны храниться в виде хешей. Нужен медленный алгоритм с солью, устойчивый к перебору на GPU.

## Решение

- `crypto.scrypt` со случайной солью 16 байт, длина ключа 64 байта, параметры по умолчанию Node
  (`N = 16384, r = 8, p = 1`).
- В `password_hash` хранится строка `scrypt$<N>$<r>$<p>$<salt base64>$<hash base64>` — параметры
  лежат рядом с хешем, их можно усилить позже, не ломая старые записи.
- Сравнение — `crypto.timingSafeEqual`.
- Пароль: от 8 до 128 символов.

## Альтернативы

- **bcrypt** — классика, но нативный модуль (те же проблемы с установкой, что в ADR 002), а
  `bcryptjs` заметно медленнее. Ещё bcrypt молча обрезает пароль после 72 байт.
- **Argon2id** — первый выбор OWASP, но в Node доступен только как нативный модуль.
- **sha256 с солью** — быстрый хеш, перебирается на GPU; для паролей не подходит.

## Последствия

- Ноль зависимостей; scrypt — memory-hard и входит в рекомендации OWASP.
- Формат строки самоописывающий: при смене параметров старые хеши проверяются по своим параметрам.
