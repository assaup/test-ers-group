# 003. Поиск по ФИО через нормализованную колонку

**Статус:** принято

## Контекст

Поиск по ФИО должен игнорировать регистр. В SQLite `LIKE` и `lower()` без расширения ICU работают
только с ASCII:

```sql
SELECT lower('ИВАНОВ');          -- 'ИВАНОВ'
SELECT 'Иванов' LIKE '%иван%';   -- 0
```

Плюс пользователи пишут то «Фёдорова», то «Федорова».

## Решение

- В `employees` есть колонка `full_name_search`. При вставке она заполняется функцией
  `normalizeForSearch` из `shared`: `trim` → схлопнуть пробелы → `toLocaleLowerCase('ru')` →
  `ё` → `е`.
- Строка поиска нормализуется той же функцией, экранируются `%`, `_`, `\`, и выполняется
  `WHERE full_name_search LIKE ? ESCAPE '\'` с `%запрос%`.
- Колонка проиндексирована.

## Альтернативы

- **Пользовательская SQL-функция** (`db.function('lower_ru', …)`) — работает, но вызывается на
  каждой строке при каждом запросе и делает индекс бесполезным.
- **Расширение ICU** — нужно собирать и подгружать, ломает идею «без нативных зависимостей».
- **FTS5** — полнотекстовый поиск с морфологией избыточен для поиска подстроки в ФИО.
- **Фильтрация в JS** — не масштабируется и переносит логику из БД в приложение.

## Последствия

- Поиск не зависит от регистра и `ё`, правило нормализации одно и покрыто тестами.
- Для `LIKE '%…%'` индекс по-прежнему не используется — для справочника на сотни и тысячи строк это
  не проблема; при росте — FTS5.
- Если когда-нибудь появится редактирование ФИО, колонку нужно обновлять в том же запросе.
