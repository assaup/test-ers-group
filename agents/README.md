# agents/

Рабочий контекст проекта: для ИИ-агентов (Claude Code) и для человека, который хочет понять, как
проект планировался и почему он устроен именно так.

| Файл                               | Что внутри                                              |
| ---------------------------------- | ------------------------------------------------------- |
| [architecture.md](architecture.md) | структура пакетов, схема БД, API, слои, поток запроса   |
| [roadmap.md](roadmap.md)           | этапы работы с чекбоксами — источник правды о прогрессе |
| [conventions.md](conventions.md)   | стиль кода, имена файлов, коммиты, ошибки, тесты        |
| [design-brief.md](design-brief.md) | задание для Claude Design: экраны, состояния, токены    |
| [decisions/](decisions/)           | ADR — короткие записи «почему так, а не иначе»          |

## Как агент работает с проектом

1. Прочитать [`CLAUDE.md`](../CLAUDE.md) в корне — там правила, которые действуют всегда.
2. Найти в [roadmap.md](roadmap.md) текущий этап и его пункты.
3. Сверить решение с [architecture.md](architecture.md) и [conventions.md](conventions.md).
   Если решение расходится с документом — сначала обновить документ (или добавить ADR), потом код.
4. Перед коммитом: `npm run lint`, `npm run typecheck`, тесты затронутого пакета.
5. Отметить сделанные пункты в roadmap.md тем же коммитом, что и код.

## Новый ADR

Файл `decisions/NNN-короткое-имя.md`, разделы: **Контекст**, **Решение**, **Альтернативы**,
**Последствия**. ADR не переписываются задним числом: если решение поменялось, пишется новый ADR,
а в старом ставится пометка «заменён NNN».
