# Дизайн-бриф для Claude Design

Задание не требует сложного дизайна. Цель — аккуратный, спокойный интерфейс внутреннего
HR-инструмента, который выглядит законченным, а не «студенческим». Без иллюстраций и анимаций ради
анимаций.

## Продукт

Внутренний справочник сотрудников компании. Пользователь регистрируется или входит по email и
паролю, видит список сотрудников (ФИО, должность, отдел), ищет по ФИО, фильтрует по отделу и
добавляет новых сотрудников. Интерфейс на русском.

## Экраны

### 1. Вход

- Поля: Email, Пароль. Кнопка «Войти». Ссылка «Нет аккаунта? Зарегистрироваться».
- Подсказка с демо-доступом под формой (email и пароль демо-пользователя).
- Состояния: обычное, отправка (кнопка заблокирована, индикатор), ошибка «Неверный email или
  пароль» над формой, ошибки полей под полями.

### 2. Регистрация

- Поля: Email, Пароль, Повторите пароль. Подсказка к паролю: «Не меньше 8 символов».
- Кнопка «Создать аккаунт». Ссылка «Уже есть аккаунт? Войти».
- Состояния: как у входа + «Этот email уже зарегистрирован».

### 3. Список сотрудников

- Шапка: название приложения слева; справа email пользователя и кнопка «Выйти».
- Панель над списком: поле поиска «Поиск по ФИО» с иконкой, выпадающий список «Все отделы» +
  отделы, кнопка «Добавить сотрудника» (основное действие).
- Счётчик: «Найдено: 5».
- Таблица: ФИО, Должность, Отдел. Отдел — в виде небольшой метки (badge), у каждого отдела свой
  приглушённый цвет.
- Состояния:
  - загрузка — скелетон строк таблицы;
  - пусто после поиска — «Никого не нашли» + кнопка «Сбросить фильтры»;
  - пусто совсем — «Сотрудников пока нет» + «Добавить сотрудника»;
  - ошибка загрузки — сообщение + «Повторить».
- Узкий экран (< 768 px): таблица превращается в список карточек, панель фильтров — в столбик.

### 4. Добавление сотрудника

- Модальное окно (`<dialog>`) поверх списка. Поля: ФИО, Должность, Отдел (select). Все обязательные,
  отмечены звёздочкой.
- Кнопки «Отмена» и «Добавить».
- Ошибки под полями после попытки отправки: «Укажите ФИО», «Укажите должность», «Выберите отдел».
- После успеха — окно закрывается, в углу появляется уведомление «Сотрудник добавлен», новая строка
  кратко подсвечивается в таблице.

## Ограничения реализации

- Только обычный CSS и CSS-переменные — без Tailwind, CSS-in-JS и UI-библиотек. Всё, что
  нарисовано, должно реалистично собираться вручную.
- Системный стек шрифтов или один веб-шрифт с кириллицей (например, Inter).
- Контраст текста не ниже WCAG AA, видимое состояние фокуса у всех интерактивных элементов.
- Светлая тема обязательна; тёмная — желательно, через те же токены и `prefers-color-scheme`.
- Ширины для проверки: 360, 768, 1200 px.

## Что нужно на выходе

1. **Токены**, сразу в виде CSS-переменных: цвета (фон, поверхность, текст основной/вторичный,
   граница, акцент, ошибка, успех, цвета меток отделов), шрифты и размеры, отступы (шкала 4 px),
   радиусы, тени, ширина контента.
2. **Макеты** четырёх экранов выше со всеми перечисленными состояниями.
3. **Компоненты**: кнопка (основная, вторичная, текстовая; обычная, hover, focus, disabled,
   loading), текстовое поле и select (обычное, focus, ошибка), метка отдела, строка таблицы,
   карточка сотрудника (мобильная), модальное окно, уведомление.
