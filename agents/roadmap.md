# Roadmap

Отмечаем пункты тем же коммитом, что и код. Формат коммитов — в [conventions.md](conventions.md).

**Каждый этап закрывается своими тестами** — этап не считается готовым, пока `npm test` не покрывает
его поведение.

## 1. Каркас и инструменты ✅

- [x] npm workspaces: `client`, `server`
- [x] TypeScript strict, общий `tsconfig.base.json`
- [x] ESLint (type-checked) + Prettier
- [x] Husky + lint-staged + commitlint (Conventional Commits)
- [x] GitHub Actions: lint, format, typecheck, build

## 2. Контекст для агентов ✅

- [x] `agents/`: architecture, roadmap, conventions, design-brief
- [x] ADR 001–004
- [x] `CLAUDE.md`
- [x] README: запуск, скрипты, раздел про ИИ

## 3. Сервер: БД и сид ✅

- [x] пакет `shared`: zod-схемы, `normalizeForSearch`, `toFieldErrors`
- [x] `db/connection.ts`: `node:sqlite`, WAL, foreign keys, путь из `DB_PATH`
- [x] миграции + таблица `migrations`, STRICT-таблицы
- [x] идемпотентный сид: отделы, 5 сотрудников
- [x] `createApp({ db })`, `AppError`, единый error handler, 404 для `/api/*`
- [x] Vitest + supertest, база `:memory:`, тесты в CI
- [x] тесты: схемы, нормализация, миграции и откат, ограничения схемы, сид, сохранение после
      перезапуска, error handler

## 4. Сервер: авторизация ✅

- [x] хеширование паролей (scrypt), генерация и хеш токена сессии
- [x] демо-пользователь в сиде (`demo@example.com` / `demo12345`)
- [x] `register`, `login`, `logout`, `me`
- [x] `requireAuth`, httpOnly-cookie `sid`
- [x] rate limit на `login` и `register`
- [x] очистка просроченных сессий при входе
- [x] тесты: scrypt и токены, атрибуты cookie, хранение только хешей, дубль email без учёта
      регистра, одинаковый ответ на неверный пароль и неизвестный email, истёкшая и отозванная
      сессия, независимые сессии устройств, rate limit

## 5. Сервер: сотрудники ✅

- [x] `GET /api/departments`
- [x] `GET /api/employees` с `search` и `departmentId`
- [x] `POST /api/employees` с проверкой отдела
- [x] тесты: сортировка, поиск (кириллица, регистр, `ё`, лишние пробелы, `%` `_` `\` как
      обычные символы), фильтр и его сочетание с поиском, пустые параметры, создание и
      появление в поиске, ошибки полей, несуществующий отдел

## 6. Сервер: сквозные сценарии ✅

Тесты отдельных модулей пишутся в этапах 3–5, здесь — проверка API целиком
([`server/tests/api.test.ts`](../server/tests/api.test.ts)).

- [x] 401 на всех защищённых маршрутах (параметризованный тест по списку маршрутов), аноним не
      может создать сотрудника, публичные маршруты доступны
- [x] сценарий «регистрация → выход → вход → список → добавление → поиск → фильтр → выход»
- [x] список сотрудников общий для всех пользователей
- [x] перезапуск сервера на том же файле БД: пользователи, сессии и добавленные сотрудники
      сохраняются

## 7. Дизайн (Claude Design) ✅

- [x] прогнать [design-brief.md](design-brief.md) через Claude Design — макет в
      [`design/`](../design/README.md)
- [x] перенести токены в `client/src/styles/tokens.css`, светлая и тёмная темы
- [x] шрифт Golos Text, базовые стили, фавикон
- [x] Vitest + jsdom + Testing Library для клиента
- [x] тест: стили используют только объявленные токены, без захардкоженных цветов; у каждого
      цветового токена есть тёмный вариант

## 8. Клиент: каркас и авторизация ✅

- [x] React Router, `AuthProvider`, `RequireAuth` / `GuestOnly` с возвратом на исходную страницу
- [x] `api/client.ts` с `ApiError`, сетевыми ошибками и глобальной обработкой 401
- [x] UI-компоненты по макету: кнопка, поле, сообщение об ошибке, логотип, спиннер
- [x] страницы входа и регистрации с валидацией общими zod-схемами, фокус на первом ошибочном поле
- [x] шапка с email пользователя и выходом
- [x] тесты: API-клиент, редиректы, валидация и ошибки сервера на формах, вход, регистрация,
      выход, автоматический выход при 401

## 9. Клиент: сотрудники ✅

- [x] таблица сотрудников + состояния загрузки (скелетон) / пусто / ничего не найдено / ошибка
- [x] поиск с debounce, фильтр по отделу, синхронизация с URL
- [x] `useRemoteData`: отмена устаревших запросов через `AbortController`
- [x] добавление в `<dialog>` с валидацией и ошибками сервера, уведомление, подсветка новой строки
- [x] метки отделов в цветах из макета, стабильный цвет для новых отделов
- [x] тесты: список и состояния, поиск с debounce и `ё`, фильтр, восстановление из URL, сброс,
      гонка медленного устаревшего ответа, добавление (валидация, успех, ошибка сервера, отмена),
      истёкшая сессия, `useDebouncedValue`, цвета отделов

## 10. Доводка ✅

- [x] адаптивность: 1200 / 768 / 360 px, таблица → карточки уже 640 px, поля 44 px на телефоне
- [x] доступность: видимый фокус, подписи у всех полей (в том числе скрытые), ошибки через
      `aria-describedby`, `aria-live` у счётчика, модальное окно на `<dialog>`
- [x] светлая и тёмная темы по `prefers-color-scheme`
- [x] Express отдаёт `client/dist` в production (`npm run build && npm start`), SPA-fallback,
      кэширование ассетов
- [x] тесты: раздача клиента; смоук-тест проверяет и API, и клиент
- [x] ручная проверка в браузере: вход, поиск с «ё», диалог, мобильная ширина, обе темы
- [ ] e2e на Playwright — не делаем: сквозные сценарии уже покрыты API-тестами и тестами всего
      клиентского приложения, а браузеры Playwright утяжеляют установку и CI
